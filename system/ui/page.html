DA

Classify skin lesion images, review every result, and train better models.

DermaAgent runs a small team of agents on the DermaMNIST benchmark. A Testing agent classifies each image with every local model and combines their votes. A Reviewer agent checks that the result agrees with the evidence. A Training agent plans and runs new experiments. A Models agent answers questions about the available models. You approve every decision that should not be taken automatically.

1

Classify images

Attach dermoscopy images with the + button, drag them onto the page, or paste them. Each result shows the vote, the confidence, the reviewer's findings and the sources.

2

Train a model

Describe the goal in plain words, or open the form. You approve the plan first; new models join the ensemble only with your approval.

Ask why an image was flagged, what a metric means, how the agents decided, or which model is best on a class. Answers use the latest result, the system state, and the models' validation metrics.

          Settings

          Choose the language model of each agent and connect providers

          Every number (probabilities, votes, metrics, promotion scores) is computed in code. A language model writes the rationale, reviews it, and proposes training runs. Without one, each agent falls back to fixed rules and everything still works, except answering questions in the chat.
          Writes the rationale for each prediction. It may change the voted class only to a class the models support; the code rejects anything else.
          A different model than the Testing agent gives a more independent review. Without one, the automatic checks still run.
          Proposes runs and reads the training curves. Without one, a fixed policy decides (plateau: lower the learning rate; overfitting: more weight decay; a class at zero recall: class weights).
          0 keeps every model. Weak models already carry little weight in the vote.
          A model is addressed as provider:model, for example anthropic:claude-opus-5-5 or ollama:qwen3.6. Providers are stored in system/config/llm.json. API keys you save here stay on this machine in system/config/secrets.json; an environment variable always takes precedence.
          Used by every agent set to "Default model". "Automatic" picks the first ready model.

          New training campaign

          The Training agent proposes each run; you approve the plan first

          A campaign is a sequence of training runs. Each run stops by itself when the selection metric stops improving; the agent then reads the curves and proposes what to change. When the campaign ends, the best model is compared with the current ensemble on validation data, and you decide whether it joins. The test split is never used.
          Optional. Without a goal, the agent targets the classes the current ensemble handles worst.
          With "Agent decides", it starts from FPViT and may switch with a stated reason.
          The plan and the promotion always need your approval.
          When reached, the run stops and the agent proposes the next step.
