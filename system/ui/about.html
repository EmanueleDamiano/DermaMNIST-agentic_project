AgenticDerma research project

Human-supervised multi-agent deep learning for dermatological image classification

DermaAgent classifies dermoscopy images from the DermaMNIST benchmark into seven lesion classes, explains each result with cited sources, and trains the models that produce it. Specialised agents divide the work, check each other, and stop for a person whenever a decision should not be taken automatically.

7lesion classes from HAM10000, at 28 × 28 and 224 × 224 pixels
5 agentsOrchestrator, Testing, Reviewer, Training and Models agents, built with LangGraph
4 architecturesFPViT, ResNet-18, EfficientNet-B0 and ConvNeXt-Tiny, combined in an ensemble
0 test accessagents read training and validation data only; the test split stays isolated

Guiding principle

Numbers come from code. Language comes from the language model.

Every quantity the system relies on (class probabilities, ensemble votes, validation metrics, training diagnoses, promotion scores) is computed in Python before a language model writes anything. The language model reasons over that evidence and over retrieved literature, and deterministic checks reject any claim the evidence does not support. When no language model is available, prediction, review and training still run, with fixed rules in its place.

The problem

A good benchmark score is not the same as a reliable result.

Data and evaluation

DermaMNIST is compact and reproducible, but it contains duplicate images, cross-split leakage and label problems, and it is strongly imbalanced: melanocytic nevi make up 67 % of the training set, while dermatofibroma and vascular lesions are about 1 % each. A model that always predicts "nevus" reaches 67 % accuracy. Scores must be class-balanced and data integrity must be checked before results can be trusted.

Explanations and automation

A generated explanation adds its own risk when it is not tied to model evidence or to a source. An agent that trains and deploys models on its own adds another: a model can reach production without anyone having verified that it improves on what was there before. The project automates the full workflow while keeping data, metrics, model promotion and review under explicit control of code and of a person.

How the system works

Five compiled LangGraph agents connected through typed state, versioned records on disk and fixed tool interfaces.

OR

Orchestrator

Reads each request. Images go to prediction. A written request is interpreted by a language model with structured output: classify, train (with the constraints the user stated), a question about the models (sent to the Models agent), or any other question, answered from the system state and the latest result. When the intent is unclear it asks instead of guessing, and it relays every pause of the other agents to the person.

TA

Testing agent

Runs every model of the ensemble on each image and combines them three ways: a soft vote weighted by validation balanced accuracy above chance (the decision), a hard vote weighted by per-class precision (a check against majority-class bias), and the most confident model (reported, never decisive). It recalls past analyses of the same image, retrieves clinical passages for the leading classes, and writes a cited rationale. The language model never sees the image and may change the class only to one the models support.

RA

Reviewer agent

Reads the Testing agent's complete trace. It runs deterministic checks, retrieves literature independently using the rationale itself as the query, and identifies the model that actually drove the decision. Any warning or critical finding marks the image for human review. It cannot reclassify an image or contradict the automatic checks.

TR

Training agent

Plans a campaign and proposes each run: architecture, hyperparameters, class weighting, and augmentation justified for dermoscopy. Each run stops when the validation metric plateaus; the agent then reads the curves, with the diagnosis computed in code, and proposes the next step. A new model joins the ensemble only if it improves it on validation data and a person approves.

MA

Models agent

Answers questions about the available models: how they were trained, their accuracy, macro-F1, AUC and ROC curves on the common validation set (DermaMNIST-C val), why a run is excluded, how the vote and the promotion work. The facts and every chart are computed in code from validation data only; a check in code rejects any figure in the answer that is not in the facts. It is read-only.

Controls built into the code

Permission boundaries are enforced by the program, not requested in a prompt.

ControlHow it is enforced
Test isolationThe Training agent reads only the training and validation splits, and the promotion gate and the Models agent only validation data. No agent loads the test split. The isolated test (/evaluate on the platform, system/evaluate.py) is a separate step, run once on the final model.
Proposal validationEvery training proposal is checked for bounds, optimizer-specific learning rates, admissible augmentation, and repeated configurations before it can run.
Autonomy gateSupervised, guarded (default) or autonomous. The level decides which runs need a person. The plan and every promotion always do.
No overwritingEach run writes to a new folder. Promotion copies the checkpoint under a new name into model/promoted/, the only folder of new models the Testing agent reads.
Bounded overridesThe language model can change the voted class only to a class with at least 0.15 soft-vote probability or at least one model's vote. Any other change is rejected and logged, and every override is raised as a review warning.
Safe defaultsWith no person available, an escalated decision is recorded as rejected, never as accepted.

Classifiers

  • FPViT, a Feature Pyramid Vision Transformer: shallow transformer heads on several stages of a ResNet-18 extractor, designed for small inputs, and at 224 × 224 with an ImageNet-pretrained extractor on the leakage-free DermaMNIST-C. The reference model; baseline_paper ships with the repository.
  • ResNet-18, EfficientNet-B0 and ConvNeXt-Tiny, adapted to 28 × 28 inputs.

Imbalance and augmentation

  • Class-weighted loss (inverse frequency or effective number of samples) or balanced sampling, as alternatives, applied to the training loss only.
  • Flips and 90° rotations are always admissible: lesions have no canonical orientation.
  • Hue jitter is capped, because colour is diagnostic. Nothing fills borders with black, which would imitate dermatoscope vignetting.

Evaluation

Class-balanced metrics, fixed rules, and a with/without comparison for every promotion.

Metrics

Accuracy is reported for comparison with the literature, but it is never a selection metric. Models are assessed on balanced accuracy, macro-F1, macro one-vs-rest AUROC, per-class precision, recall and F1, and the confusion matrix.

Promotion gate

The ensemble is scored on the common validation set (DermaMNIST-C val) with and without the candidate, every model at its own input size. The report gives the change in balanced accuracy and in per-class recall; a gain below 0.005 is treated as noise. Absolute numbers are optimistic because vote weights and evaluation share the validation split, but the comparison is fair.

Confidence rule

High when the three views agree, the gap between the top two classes is at least 0.25 and the soft vote is at least 0.5. Low when the soft and hard votes disagree or the gap is below 0.10. Medium otherwise.

Explanation and sources

After the vote, the Testing agent retrieves passages from a curated knowledge base of 120 passages from five StatPearls chapters and four journal articles for the two leading classes and their differential diagnosis. Every cited passage is verified in code. The platform exposes the full context each language model received.

Intended use and limitations

DermaAgent is a research prototype. It works on low-resolution benchmark images (28 × 28 and 224 × 224 pixels), which the MedMNIST authors do not position for clinical use. Its outputs are not a diagnosis and must not guide the care of a real person. Clinical diagnosis, treatment advice, hospital deployment and private patient data are outside the project's scope.

Known limitations: the official DermaMNIST split contains duplicates and leakage, so every model is weighted and compared on the leakage-free DermaMNIST-C validation split, but the Training agent still trains on the official one; minority classes have few validation images, so differences below about 0.01 are noise; and at 28 × 28 pixels any visual attribution is coarse evidence at best.
